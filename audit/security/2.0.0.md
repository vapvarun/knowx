# Security review - KnowX 2.0.0

Reviewed 2026-10-11 on master before tagging. Scope: the whole theme (127 own PHP files, 16 JS files, no bundled libraries, no vendor code in the zip).

## Result

No finding blocks the release. One hardening change was made during the review.

## G1 - mechanical sweep (`security-sweep.sh`)

- CRITICAL patterns: none (`permission_callback => __return_true`, `wp_ajax_nopriv_`, `eval`, `unserialize($_POST)`, user-controlled `include` or `call_user_func`).
- MEDIUM `no-abspath-guard`, 97 files: accepted. These are template files and class or function files with no code that runs on load; WordPress.org theme review does not require a guard, and nothing in them is reachable except through WordPress. Files with side effects at load (`functions.php`) are loaded only by WordPress.
- Routes: the theme registers no REST routes and no AJAX actions.

## G2 - authorisation

The theme exposes four write paths, all reached through core screens or endpoints:

| Path | Who may use it | Guard |
|---|---|---|
| Category icon, accent, order and start link (`save_term_fields`) | Users who can edit the term | Core verifies the term form nonce; the handler now also checks `edit_term` for the term (added in this review; before, it relied on core alone). Subscriber: denied, admin: allowed (checked with `user_can`). Values are sanitised (`sanitize_icon`, accent colour check, `absint`, `esc_url_raw`). |
| Applies to version box (`save_version`) | Users who can edit the post | Own nonce `knowx_version` plus `edit_post`; `sanitize_text_field`. |
| `menu_order` REST field on posts | Users who can edit the post | `update_callback` checks `edit_post` for that post; the value is cast to an integer. Reading it returns a number that is already public through ordering. |
| Registered term meta (`show_in_rest`) | Users who can manage categories | `auth_callback` uses `manage_categories`; the icon is sanitised by `sanitize_icon`. |

Customizer settings are saved through the Customizer, which checks `edit_theme_options`; every colour passes `sanitize_color`, every switch is cast to 0 or 1.

## G3 - code review notes

- Output escaping: PHPCS (WordPress-Extra) reports 0 errors. The inline colour rule printed in `<head>` (`knowx-tokens`) is built only from validated values (`sanitize_color` accepts hex, rgb and hsl and nothing else).
- JavaScript: `innerHTML` is used twice. One writes a fixed SVG string (back to top button); the other copies the dropdown markup the theme itself rendered. No `eval`, no `document.write`.
- No outbound requests from the front end (checked in the network list) and no user-supplied URL is fetched on the server, so there is no SSRF surface.
- No file upload handler, no custom SQL, no `unserialize`.
- Search uses the core REST endpoints; nothing is added to them except the `menu_order` field above.
- Comments and the search form are core.

## Scanner-visible but safe

- `$_POST` reads in `save_term_fields` and `save_version`: reached only after core's nonce check or the theme's own, then capability checks.
- `phpcs:ignore` on the inline `<style>` echo in `action_print_tokens`: the CSS is generated from validated values only.

## Plugin Check / Theme Check

Theme Check plugin on the built zip: no errors, one advisory warning (the core `default` text domain for the stock Uncategorized string).
